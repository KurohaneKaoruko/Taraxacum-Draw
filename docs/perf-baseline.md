# 性能基线（task 2.7）

> 方法论：算法层 CPU 耗时（`flutter test test/performance`，Debug 模式 Dart VM），
> **非**真实 GPU 帧时序。真实 60fps（performance overlay + 真机 500 笔连续绘制）
> 在 task 7.2 补测并更新本表。

## 压测环境

- 数据规模：500 笔 × 200 点/笔（含 10% 橡皮笔迹）
- 平台：Windows 11 / Flutter 3.41.2 Debug

## 结果（2026-10-04）

| 指标 | 耗时 | 说明 |
|---|---|---|
| 顺序入账 500 笔（快路径） | **36 ms** | ≈ 0.07 ms/笔，O(1) 追加 |
| 图层缓存全量重录（500 笔） | **65 ms** | 每笔完成时触发一次；绘制中笔画不触发 |
| 全量重放（502 条 op） | **6 ms** | 乱序到达/清空/图层操作触发 |
| 撤销后重建 | **4 ms** | 同上 |

## 解读

- 单笔完成的缓存重录代价随笔迹数线性增长（500 笔 65ms ≈ 0.13ms/笔）。
  按 60fps 预算（16ms/帧）当前规模完全无压力；达到 ~1 万笔时单次重录
  预计 ~1.3s，将由快照机制（task 5.6）+ 必要时的分块缓存承接。
- 全量重放 6ms/500 op 意味着中途加入补齐（task 5.3）1 万 op 约 120ms，
  远低于设计目标。
